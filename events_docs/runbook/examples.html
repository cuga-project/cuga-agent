Three ways to run any of these

Everything below is an utterance. You send it one of three ways. Set $APP to your deployment's public URL (on Code Engine, its route) and $GW to GATEWAY_TOKEN.

Ask-anything is instant, zero setup. The NOW examples answer in one turn. The CRON/POLL examples arm a flow (you'll get an "ARMED … Watch id" reply), then fire on their own schedule — watch them in $APP/api/events/subscriptions and $APP/api/events/runs, or $APP/api/events/dashboard.

NOW — ask anything (instant)

A plain question runs the agent directly (the NOW fast-path). The price/news/weather are live tool calls, so they can't be memorized. Try these from any channel.

Live data & markets

  • what's the current price of bitcoin, and what's new from OpenAI and Anthropic this week? — the best opener: live finance + live web in one
  • what is the current price of bitcoin in usd?
  • what's the weather in Tokyo right now?
  • give me a market brief on the S&P 500 today

Knowledge, geography, memory

  • what is the capital of Japan? — then follow with "and its population?" to see per-thread memory hold

CRON — scheduled digests (native scheduler)

These arm a fixed-clock flow on the in-process scheduler — no AP. The reply is delivered back to the channel you armed it from. (For a fast demo, phrase it as "every minute…".)

  • every day at 9am send me new arXiv papers on mixture-of-experts
  • every weekday at 8am send me a market brief
  • every morning at 8am tell me what's new on https://hnrss.org/frontpage
  • every hour post the top trending GitHub repos in this channel
  • every day at 9am send me the price of bitcoin
  • every morning at 7am send me the weather in New York
  • every Monday at 9am send me a research digest on parameter-efficient fine-tuning
  • /automate the market brief every weekday at 8am — the slash form skips the LLM router
  • every minute send me the price of bitcoin — demo cadence: fires within ~1–2 min

POLL — watch & report only on change (stateful)

A poll re-checks on an interval but only speaks when something changed — the poll-state gate (threshold / identity / fuzzy). Arm one, then let it tick.

  • watch bitcoin every 2 minutes and ping me on any move — threshold
  • every 5 minutes check for new MoE papers and tell me only if there are new ones — identity (new items)
  • every 15 minutes check this RSS feed and message me new items — identity
  • check the New York weather every hour and ping me only if rain is forecast — fuzzy
  • watch bitcoin every 5 minutes and ping me on a 5% move — explicit threshold
  • watch IBM stock for the next hour and tell me if it moves — a bounded poll (ends itself)

WEBHOOK — POST an event in (no channel needed)

Any external system can POST JSON to /api/events/hook/<name>. Two modes: pinned (an agent you name) or routed (?route=1, the concierge picks the agent like a chat).

# pinned — the incident_triage agent triages an alert
curl -s $APP/api/events/hook/alerts?key=$WEBHOOK_KEY \
  -H 'content-type: application/json' \
  -d '{"alert":"HighCPU","service":"checkout-api","value":97,"threshold":85}'
# → { ok, agent:"incident_triage", answer:"P2 · checkout-api CPU 97% > 85% …", trace_id }

# routed — CUGA picks the agent, like a chat message
curl -s $APP/api/events/hook/ci?route=1&key=$WEBHOOK_KEY \
  -H 'content-type: application/json' \
  -d '{"pull_request":{"title":"Refactor auth","additions":40,"deletions":12},"repo":"acme/api"}'
# → { ok, routed:true, agent:"pr_reviewer", answer:"…" }

Utterance forms of the same idea: "when my system POSTs to my webhook, run the triage agent and reply" · "when my CI posts a failed build, triage it and tell me what broke" · "when a lead form is submitted, summarize it and post to our channel".

DIRECT reactions & channel watchers (no AP)

Because Slack/Discord/Telegram arrive over their own streams, "when someone reacts…" and "when a message is posted…" watchers are direct — no Activepieces. Arm one from that channel, then trigger it there.

  • when someone reacts with :bug: in #incidents on discord, triage the message
  • when a message gets a :bug: reaction, triage it as an incident and thread the summary
  • when a message is posted in #incidents, triage it and thread a severity
  • when someone DMs the bot, route it to the right agent and reply
  • when I react :bookmark: to a message with a link, research the topic and DM me
  • when a new member joins the server, greet them and point to the resources
  • when a new channel is created, post a welcome and suggest a charter
  • when I send the bot a link, summarize the page and reply
