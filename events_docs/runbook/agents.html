Agents & examples per agent

Which roster is this? This page documents the full 27-agent example roster (rosters/supervisor_agents_full.yaml). What actually ships and deploys is the 8-agent no-AP roster in supervisor_agents.yaml: pricebot · weatherbot · geobot · wiki_dive · webpage_summarizer · code_auditor · pr_reviewer · incident_triage. Ask the running server which one it loaded: GET /run/agents on cuga-core — the roster belongs to whoever executes. For what to type against the shipped 8, see AUTOMATION_COOKBOOK.md.

The 27 specialists in the FULL example roster, and ~10 things to try with each. Every example below is chattable with zero Activepieces — you just say it in any channel and the supervisor picks the agent. Where an agent also has a trigger, it's marked no-AP or (needs AP).

How routing picks an agent

There is one addressable agent, cuga — a supervisor (EVENTS_SUPERVISOR=1) that reads its roster (supervisor_agents.yaml) and delegates each turn to exactly one specialist, whose answer bubbles up. The concierge never picks the specialist; the supervisor does, inside runtime.run("cuga"). You don't name an agent — you just ask, and the metadata footer (— <agent> · <tools> · <ms>) tells you who answered.

Tools are the remote cuga-* MCP servers: cuga-finance (quotes) · cuga-web (search / fetch / feeds / youtube / weather) · cuga-knowledge (arXiv / wikipedia) · cuga-geo (geocode / hikes) · cuga-code (analyze) · cuga-text (summarize / extract). A specialist's triggers come from its HANDLES line; direct-channel + cron/poll/rss/webhook triggers are no-AP, SaaS-push (gmail/github/box/calendar/pinterest/youtube) needs AP.
