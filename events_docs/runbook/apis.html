1 · The universal seam

MethodPathPurposeAuth
POST/invokeRun an agent (or the concierge router) on an Envelope. Owns delivery, run-logging, the poll-delta gate, and bounded-run expiry. Called by channel adapters, the scheduler, webhooks. Response: {ok, agent, answer, trace_id, meta{agent,backend,mcp,tools,ms}} (+ poll{changed,reason} for a poll tick).gateway

5 · Inbound webhooks & direct pollers

MethodPathPurposeAuth
POST/api/events/hook/{name}Generic inbound webhook → run an agent on the JSON body, optional channel delivery. Pinned ?agent= (default incident_triage) vs routed ?route=1 (concierge picks). Response {ok, routed, agent, answer, delivered, trace_id}.?key
POST/api/events/box/pollDirect Box poller (EVENTS_BOX_BACKEND=direct): poll a folder for new files/folders/comments → fire an agent per item. No AP.gateway
POST/api/events/synth-fireFire any registry trigger with a synthetic, piece-exact payload at the seam — no AP flow/connection (tests AP-type triggers without AP). Off when EVENTS_DEBUG_RUN=0.gateway

7 · OAuth connect AP · out of scope

Listed for completeness — these create/read Activepieces connections and are not part of the no-AP path: GET /api/events/connect/{app}, GET /api/events/connect/{app}/callback, POST /api/events/connect/{app}/token, GET /api/events/connections.

Which routes are no-AP? The seam, all chat surfaces, subscriptions/runs, every read endpoint, /api/events/hook, /api/events/box/poll, /api/events/synth-fire, and direct-channel arm all work with zero Activepieces. AP is required only for OAuth connect/*, /connections, AP-backed arm, and the AP portions of runs / {id}/flow / {id}/run.
