The Envelope — the one data contract

Every inbound trigger is normalized into an Envelope (three stable string fields + source + event). validate() rejects a malformed one with 400 before anything runs.

FieldType · defaultMeaning
source.typestr · "channel"one of channel · integration · time (validated)
source.namestr · "web"the concrete connector: telegram/slack/discord, or cron/poll for a tick
source.thread_idstr · "web:local"keys per-conversation memory; channels use gw:<channel>:<native>
source.userstr · ""the channel-native author id → per-user identity/scope (empty → falls back to the thread-native id)
event.kindstr · "message"normalized (hyphens→underscores, lowercased); must be a registry kind — message, tick, new_pr…
event.payloaddict · {}the trigger's data (for a channel: {telegram_user: …}; for a push: the event body, with a _raw fallback)
textstr · ""the utterance (required non-empty for a channel+message envelope)
agentstr|None · Nonethe target: "concierge" (the router) or a concrete agent id
deliverbool · falsetrue → the seam delivers the answer over the origin transport; false → the caller (channel handler) delivers it
scopestr · ""the isolation scope (tenant/instance/user); empty → /invoke resolves it (identity map or headers)
trace_idstr · ""end-to-end correlation id

Not envelope fields: subscription_id and expires_at are top-level keys the scheduler adds to the raw /invoke body and the handler reads directly (bounded-run expiry, poll-state lookup) — from_dict ignores them.

What the agent actually receives — worker_input()

The agent doesn't see the raw envelope; it sees a rendered prompt. For a channel message that's just text. For a non-chat event (a push, a tick) the payload is rendered into an [event] line and framed as a one-shot instruction:

# worker_input() — envelope.py
channel message        ─▶  returns self.text verbatim
integration event      ─▶  "<text>\n\n[event] k1=v1  k2=v2 …"   # each value capped 1500 chars
                            # if curated payload empty but payload._raw present → "raw=<json>" (capped 4000)  [Tier-0 net]
                            # PUSH framing prepends: "A watched event just occurred — the [event] line is
                            #   its authoritative data … Handle THIS event now, once … reply with the content."

Inside /invoke — the pipeline

One handler, every trigger. The order is load-bearing (auth first; scope before routing; expiry before running the agent).

POST /invoke · header X-Gateway-Token · app.py ~167–426
1
authenticate
if token and X-Gateway-Token != token → 401
Empty GATEWAY_TOKEN leaves the seam open (a startup warning fires). The channel handlers, the scheduler, and webhooks all send this header.
2
validate + parse
envelope.validate(body) → 400 on problems · env = Envelope.from_dict(body)
Rejects unknown source.type/event.kind and an empty-text channel message.
3
resolve scope (isolation)
scope = env.scope · else channel author → identity map (resolve_channel) · else resolve_principal(headers)
Everything downstream keys off scope: memory, agent lookup, subscriptions.
4
bounded-run expiry gate
if body.expires_at and now > expires_at → delete the subscription, return {expired:true} — do NOT run
Lazy enforcement of "… for one hour": a flow never outlives its deadline by more than one tick, even if the server was down. See NL→Flow §bounded.
5
account-link · poll augment
"/start <token>" | "/link <token>" → bind channel id → user · POLL: env.text += augment_prompt(watch_state)
The link handshake makes a sender's native id map to a profile. For a POLL tick, the change-detection instruction is appended (see Scheduler §poll).
6
direct-watcher interception
if agent=="concierge" and channel message and a direct_events watcher matches → agent = watcher.target_agent
An armed "when someone reacts :bug: in #incidents…" reassigns the target from the router to the specialist. Only for channel messages, never for a slash.
7
fork on agent (below)
agent=="concierge" → concierge.run(…) · concrete id → runtime.run(…) · else 404
This is the whole branch.
8
footer · poll-gate · deliver · log
runmeta.footer → poll_state.decide → if deliver and changed: delivery.send_direct → log run
Appends "— agent · tools · ms" (if EVENTS_REPLY_METADATA), gates delivery on real change (poll), and delivers back over the origin transport. Returns {ok, agent, answer, trace_id, meta}.

The fork (verbatim shape)

# app.py — the routing branch
if agent == "concierge":                        # every channel message; the router
    answer = await concierge.run(env.thread_id, env.text, principal)
else:                                          # a concrete agent id (a tick, a push, a watcher)
    if not agent or runtime.get_agent(agent, scope=agent_scope) is None:
        return 404 { "ok": false, "error": "unknown agent '<agent>'" }
    answer = await runtime.run(agent, env.thread_id, env.worker_input(),
                               scope=agent_scope,
                               deliver_to=[env.source.name] if env.deliver else None)

A channel chat carries agent:"concierge" → the router. A scheduler tick or a webhook carries a concrete id (or the router, with ?route=1). A falsy/unknown agent returns 404 — there is no silent default.

The concierge — chat, or arm a flow?

The concierge is not an LLM wrapper around every message. A plain question skips the LLM entirely. run() decides in this order — first match wins:

# concierge.py — run(thread_id, text, principal)
1. parsed = _slash_parse(text)              # /automate /watch /schedule /cron /poll /push /start /link
   if parsed: return _arm_slash(…)          #   → deterministic arm, NO LLM

2. pre = await _pre_route(…)                # flowspec: a parked-answer to a prior question,
   if pre is not None: return pre           #   or a high-confidence "watch X" → arm it (or ask ONE question)

3. if EVENTS_NOW_FASTPATH and classify.classify(text) == "NOW":   # heuristic regex
       return await runtime.run("cuga", thread(f"{tid}:cuga"), text, scope=…)  # STRAIGHT to the agent

4. res = await self._graph.ainvoke({"messages": [HumanMessage(text)]}, …)     # the LLM react-agent
   return res["messages"][-1].content       #   standing intent (cron/poll/push phrasing) → tool-calling

So a chat ("what's IBM's stock price?") is classified NOW by a dependency-free regex and runs the agent directly — no concierge-LLM hop. Only standing phrasing ("every weekday…", "when a PR opens…") engages the concierge's own LLM react-agent, whose tools then answer or arm. The full NL→Flow path — the tools, cadence-stripping, how a native subscription is written — is its own page.

One brain, three doors

runtime.run("cuga", …) builds/reuses the agent's DynamicAgentGraph and drives it with CUGA's AgentLoop — the identical path the browser's /stream uses. In supervisor mode the one agent cuga routes to a specialist internally and the answer bubbles up. The three entry points differ only in the door; the agent is never forked:

DoorEntryHow it reaches the agent
ChannelsCUGA /run via cuga_door.ask()CUGA decides: plain chat → the supervisor answers directly. A slash verb (or an open arming dialogue) → forwarded to /api/concierge. Channels no longer touch /invoke.
Web chat/stream (same rule) · /api/conciergeplain question streams the agent directly; a slash verb → concierge, returned as one SSE Answer frame
Flows/invoke (concrete agent)a tick/webhook → runtime.run(agent) directly on the payload
The whole path, one line: envelope → /invoke (auth · scope · expiry · link · poll-augment) → fork on agent → { concierge: slash · pre-route · NOW→agent · LLM-router | concrete: agent } → runtime.run("cuga") → DynamicAgentGraph via AgentLoop → answer → metadata footer → poll-gate → deliver.

Delivery & the metadata footer

When deliver:true (scheduler ticks, webhooks that name a sink), the seam sends the answer itself via delivery.send_direct, decoding the gw:<channel>:<native> origin from thread_id — the same direct transports the channels use (no AP send step). When deliver:false (channel chats), the channel handler owns the round-trip. If EVENTS_REPLY_METADATA is on, a compact footer is appended: — <sub-agent> · <tools> · <ms>, surfacing which specialist actually answered.
