The decision ladder

An utterance enters concierge.run() and is decided in order — the cheapest path that matches wins. Only the last rung is an LLM.

#RungMechanismOutcome
1Slash — /automate /watch /schedule /cron /poll /push /start /link_slash_parse — deterministic, no LLMarm directly in the named mode (/automate lets the router pick)
2Pre-route — a parked answer, or a high-confidence "watch X"_pre_route over flowspecarm it, or ask exactly one clarifying question (slot-fill)
3NOW fast-path — a plain questionclassify.classify() — heuristic regexstraight to the agent, no concierge-LLM hop
4Standing intent — "every…", "when…"the concierge's LLM react-agent (tool-calling)tools answer_now / find_or_create_flow answer or arm

The heuristic classifier (rung 3)

classify.classify(text) is a dependency-free regex, not an LLM. It returns NOW | CRON | PUSH | POLL, checked POLL→PUSH→CRON→NOW. It exists to make the NOW fast-path free, to route /stream, and to be the oracle for dry-runs — it is not the real NL→intent decision.

# classify.py — the signals (regex, illustrative)
POLL  ← "every N minutes … tell me if / ping me on / watch"   # recurring + change-report
PUSH  ← "when a … arrives / opens / is filed / reacts"       # event-driven
CRON  ← "every day at 8am / weekday / hourly"               # fixed clock
NOW   ← everything else                                  # a plain question
The real classifier is the LLM react-agent (rung 4). When the heuristic says a message is not NOW, the concierge hands it to its own tool-calling LLM, which decides the mode by which tool it calls (find_or_create_flow(kind=…)) rather than by keyword. The heuristic is the fast gate; the LLM is the judge.

The concierge's LLM tools

Rung 4 is a create_react_agent over exactly these tools. It either answers immediately or arms one flow, then explains what it did.

ToolSignatureDoes
list_capabilities() → strreports the one agent (cuga) and its reach — grounding for the LLM
answer_now(agent, task) → strforces agent="cuga" and runs it once — the immediate-answer path (same agent as the NOW fast-path)
find_or_create_flow(agent, kind, prompt, every_minutes?, cron?, source?, event?, deliver_to?, repo?, label?, folder?, emoji?, pattern?, watch_channel?) → strarms a standing flow. kind ∈ {cron, poll, push}. De-dups on a dedup_key so re-asking reuses the flow.

Both answer_now and the NOW fast-path call the identical runtime.run("cuga", …) — "same agent, either way." find_or_create_flow is only offered when a subscription store is present.

Arming a native cron / poll (no AP)

When find_or_create_flow(kind="cron"|"poll", …) runs and the native scheduler is enabled (EVENTS_SCHEDULER != "ap" — the default), it writes a native subscription and returns. There is no Activepieces call.

find_or_create_flow(kind, prompt, …) · concierge.py
1
strip the cadence
task = await _single_shot_task(prompt) # "watch bitcoin every 2 min" → "Check the price of bitcoin now"
The schedule owns recurrence, so the stored prompt is a single run. LLM-first, regex fallback (§cadence).
2
frame it as one run
run_prompt = "This is ONE run of a scheduled task … do NOT loop, sleep, or wait. Do the check ONCE."
Prevents the agent from trying to implement the schedule itself (loop + sleep → execution timeout).
3
read the bound (if any)
ttl = classify.ttl_of(raw_utterance) → expires_at = now + ttl
"… for one hour" is read from the raw utterance (the rewrite drops it). See §bounded.
4
write the native subscription
store.upsert(Subscription(backend="native", source_type="time", source_connector="cron"|"interval", …))
Sets interval_seconds or cron_expr, next_fire, expires_at, deliver_to=[sink], thread_id, prompt=run_prompt. No engine/AP call.
5
POLL only — seed the delta state
spec = poll_state.extract_spec(utterance) → store.set_watch_state(spec_to_state(sub.id, spec))
Classifies the watch into threshold / identity / fuzzy so later ticks only report on real change. See Scheduler §poll.
# the native Subscription that gets written (illustrative fields)
Subscription(
  mode="POLL", backend="native", target_agent="cuga",
  source_type="time", source_connector="interval",
  interval_seconds=120, cron_expr="", next_fire=<now+120>, expires_at=0,
  prompt="[one run] Check the price of bitcoin now and report the move.",
  deliver_to=["telegram"], thread_id="gw:telegram:111222333", dedup_key="…" )
// reply → "ARMED poll for cuga → telegram (native · no AP). Runs every 2 min. Watch id cuga-8ab9cf."

Cadence-stripping — _single_shot_task

A recurring utterance is rewritten to a one-run task so the stored prompt never re-encodes the schedule. LLM-first, regex fallback:

# concierge.py — _single_shot_task(prompt)
if EVENTS_CADENCE_LLM != "1":  return _strip_cadence(prompt)          # regex only
out = <LLM rewrite via _REWRITE_SYSTEM, timeout EVENTS_CADENCE_LLM_TIMEOUT=20>
if out leaks cadence words (_CADENCE_LEAK) or balloons (>4×):  out = _strip_cadence(prompt)
return out
# _strip_cadence: removes "every N <unit>", "hourly/daily/…", "at 9am"; rewrites "keep watching"→"check"

Env: EVENTS_CADENCE_LLM (default 1) · EVENTS_CADENCE_LLM_TIMEOUT (20). The rewrite is one call per flow, never per tick.

Bounded runs — "… for one hour"

Add a duration and the flow ends itself. The TTL is parsed from the raw utterance (classify.ttl_of), stored as expires_at on the subscription, and enforced lazily at /invoke:

# app.py — at the top of /invoke
_exp = body.get("expires_at")
if _exp and time.time() > float(_exp):
    <delete the subscription>
    return { "ok": true, "expired": true,
             "answer": "This bounded flow reached its end time and has been removed." }
# the native scheduler retires it too: a due row past expires_at is deleted before firing.

Lazy on purpose: it works even if the server was down at the deadline, and a flow never overshoots by more than one tick.

Direct channel watchers (push, no AP)

A "when someone reacts :bug: in #incidents…" is armed as a direct watcher — no AP, because the reaction already arrives over the channel's own stream (Slack Events API / Discord Gateway). At /invoke, an armed watcher intercepts a matching channel event and reassigns the target from the router to the specialist:

Direct watcher · arm + match
1
arm
"when someone reacts :bug: in #incidents, triage the message" → a push subscription (source=slack, event=new_reaction, emoji=bug)
Stored in the same subscription store; no AP flow.
2
event arrives
Slack Events API → /api/events/slack/events → the reaction is a non-message event → direct_events.match
The channel's own inbound stream carries the reaction (see Channels §Slack).
3
dispatch to the specialist
match → /invoke with agent = watcher.target_agent (e.g. incident_triage), deliver back to the thread
The router is bypassed; the named agent runs on the event payload.

Worked example, end to end

"watch bitcoin every 2 minutes and ping me on any move", said in Telegram:

1. Telegram getUpdates → /invoke (agent="concierge", text="watch bitcoin every 2 minutes …")
2. concierge.run → not slash, not pre-route, classify → POLL (not NOW) → LLM react-agent
3. LLM calls find_or_create_flow(kind="poll", prompt=…, every_minutes=2, deliver_to="telegram")
4. _single_shot_task → "Check the price of bitcoin now"; write native Subscription(interval=120s);
       poll_state.extract_spec → watch_state(kind="threshold" or "fuzzy")
5. reply: "ARMED poll … Runs every 2 min. Watch id cuga-8ab9cf." → back to Telegram
6. <every 120s> native scheduler → POST /invoke (source=time, kind=tick, deliver=true, subscription_id)
7. /invoke augments the prompt with the [WATCH] instruction; runs cuga; parses <<SIGNAL {…}>>
8. poll_state.decide → changed? deliver the answer to Telegram : suppress (log "nochange")

Steps 6–8 are the Scheduler & Polling page.
