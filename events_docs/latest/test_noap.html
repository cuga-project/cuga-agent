CUGA · events · runbook

Test the channels — without Activepieces

Bring CUGA up with zero AP and prove each chat channel works, end to end. ~10 minutes. You never start a container or a tunnel (unless you want to test Slack).

What you're testing: the NOW / chat trigger on web telegram discord — a message in → the concierge answers → the reply comes back. No AP, no tunnel. slack is optional and needs a public URL (see §5).

0 · Prerequisites (2 min)

You only need Python deps and at least one bot token. Nothing else — no podman, no ngrok.

# one-time, if not already done
uv sync --python 3.12          # builds .venv
cp .env.events.example .env    # then edit .env — see below

Minimal .env for the no-AP channel test:

KeyNeeded forNotes
EVENTS_ENABLED=1allturns the events layer on
GATEWAY_TOKEN=…all channelsany string — guards the internal /invoke hop
LLM keyallWATSONX_* or OPENAI_API_KEY — the concierge needs a model to answer
TELEGRAM_BOT_TOKEN=…telegramfrom @BotFather. Optional if you only test web/discord.
DISCORD_BOT_TOKEN=…discordDeveloper Portal → Bot. Enable Message Content Intent.

You do not set EVENTS_TELEGRAM_BACKEND — direct is the default. make up-noap forces it anyway.

1 · Bring CUGA up — no AP, no tunnel

make preflight-noap     # checks uv + .venv only (fails loud if missing)
make up-noap            # boots the events layer, arms channels, prints what's live

Expect it to end with:

✓ CUGA up — NO Activepieces.   Chat channels live: web · Telegram · Discord.
   NOW-trigger (chat) works fully. cron/poll/push + Slack + AP integrations are OFF …
   → NEXT: make status

2 · Confirm the capability tier

make status

In the output you should see the boot capability report confirm the no-AP tier:

✓ web chat · webhooks · direct watchers (Slack/Discord/Box-direct · Telegram-direct)
   — no extra infra (Telegram chat runs AP-free via long-poll)
✗ Activepieces not reachable → cron/poll + AP-backed integration triggers unavailable
✗ no EVENTS_PUBLIC_URL → …  [Telegram chat still works — it's direct/outbound]

Those two ✗ lines are expected and fine — they're the AP/tunnel tiers you deliberately skipped. The channels section of make status should show web/telegram/discord present. In the logs (make logs) look for telegram long-poll started as @yourbot and discord gateway READY.

3 · Test each channel by hand

web — the zero-dependency one

Open http://localhost:7860 and chat, or curl it directly (no token needed):

curl -s localhost:7860/api/concierge \
  -H 'content-type: application/json' \
  -d '{"text":"say hello in 5 words","thread_id":"web:test"}' | python3 -m json.tool
{ "ok": true, "reply": "Hello there, nice to meet!", "trace_id": "…" }

Note: the browser-facing /api/concierge returns the text under reply (the internal channel→/invoke hop uses answer).

telegram — DM the bot

  • Open Telegram, find your bot (the @username from BotFather), send “what's the price of bitcoin?”
  • Expect a reply within a few seconds, as a reply to your message.
  • Watch it fire: make logs → telegram.reply chat=… ok=True.
  • Group chat? By default (EVENTS_TELEGRAM_CHAT=all) it answers everything. Set =mention to require @yourbot in groups (private DMs always answer).

discord — @mention the bot

  • Invite the bot to a server, then in a channel type “@yourbot what's the price of bitcoin?” (or DM it).
  • Expect a reply referencing your message.
  • If nothing happens: the #1 cause is Message Content Intent OFF — Developer Portal → Bot → Privileged Gateway Intents → enable it, then make reload. A disallowed-intents gateway logs error 4014.

4 · Or run the automated channel check

One command drives the channels the same way — without the AP-dependent flow modes:

make test-live ARGS="--only channels"

This exercises web (full round trip), Telegram and Discord (drive + verify), and Slack (skipped unless configured). Per-channel checks also exist if you want to isolate one:

5 · Slack (optional — the one that needs a URL)

Slack is inbound — it POSTs events to you — so it's the only channel that needs a public URL. "No AP" ≠ "no tunnel" for Slack (it's still fully AP-free; it just needs to be reachable).

  • Local, still no AP — the clean way: 
    make up-noap-slack
    Boots the events layer with no Activepieces but with the CUGA tunnel, so all four channels (web · Telegram · Discord · Slack) work. Then set the Slack app's Event Subscriptions Request URL to <public>/api/events/slack/events — make status prints the exact URL.
  • Deployed (Code Engine): no tunnel needed — point Slack at the CE route. See the cloud section of channels_without_ap.html.
Reading the capability report: after make up-noap (no tunnel), make status honestly says "public URL is CONFIGURED … but NO tunnel is running → Slack won't arrive". After make up-noap-slack it flips to "public URL set … can reach you". That line now reflects a running tunnel, not just a value in .env.

6 · Troubleshooting

SymptomFix
Telegram silentIs TELEGRAM_BOT_TOKEN set? make logs should show telegram long-poll started. Another process polling the same bot steals updates — only one poller per bot.
Discord silentMessage Content Intent off (error 4014) — enable it, make reload. Also confirm the bot is in the server + can read the channel.
"no answer" in logsThe concierge has no LLM key — set WATSONX_*/OPENAI_API_KEY, make reload.
Everything 401/invoke failsGATEWAY_TOKEN mismatch — it must be set in .env (the channel handler and /invoke read the same one).
Want the AP path backSet EVENTS_TELEGRAM_BACKEND=ap + make reload + make channels (needs AP + tunnel).
