How agents are hosted

The classic CUGA server and the events layer's single-agent world — told from the agent's perspective, because that's where the confusion lives. (The interim multi-agent fleet this project briefly ran is covered at the end, as history.)

“Every request that reaches this process is for me. My name is hardcoded (cuga-default). My skills are the server's config. If I have sub-agents, they're my private staff — nobody outside can address them.”

The events world today — the SAME shape, with a dynamic staff

The single-agent world (ADR-0009, plan + live proof) deliberately returns to the classic shape: one addressable agent — cuga — and finishes what main's supervisor mode started, by giving it a canonical, editable roster and an event-driven front.

“I'm cuga. Channels talk to me, triggers wake me, webhooks name me — always me. My specialists are YAML entries, not deployments: they get event content and their own tools, never a token, never a channel. When I'm woken, I read the event and pick exactly one of them; their answer is my answer. My routing isn't taken on faith — it's a gated benchmark (make test-delegation: 14/14, zero self-answers on the first full run).”

The one-line summary: the events world is the classic single-agent server, plus an event-driven front (channels, triggers, webhooks → one envelope) and a dynamic, canonical roster — same shape, more ways to be woken, and routing you can measure.

History — the interim fleet (retired 2026-07-15)

Between the classic server and today's model, this project ran a multi-agent host: 27 independently-addressable agents in a sqlite registry (AgentStore), agent-picking at the concierge, and flows bound to a specific agent at arm time (push-github-new-pr-pr_reviewer). It worked and was fully live-proven — but it forked the agent model from CUGA-main (two definition interfaces, two routing shapes), and reading this page used to require understanding both. ADR-0009 retired it: the registry became the YAML roster, arm-time binding became supervisor routing (with the delegation benchmark as the price-of-admission gate), and the agents CRUD API returns 410. What the fleet got right — the /invoke seam, the trigger registry, per-user credentials in AP — is exactly what survived into the current model.
