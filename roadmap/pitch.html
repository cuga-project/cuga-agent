Before the flows — setup time

An agent is built with tools. Channels & integrations are wired in at setup.

Anatomy of an agent

agent resume_judge skill judge a resume vs a JD tools cuga-text (MCP) chans telegram · web integr box · gmail (per-user) access builder · admin
A builder sets this up once. The concierge never creates agents — it only routes to the ones that exist (or declines).

What the wiring means

  • Agent + channel → a conversational agent.
    geobot = geo skill + cuga-geo tool, on Telegram → you ask, it answers there.
  • Agent + channel + integration → a watcher/actor.
    resume_judge watches Box, judges with its tools, delivers to Gmail / Telegram.
Channels = where it converses & delivers · Integrations = what it watches & acts on — both chosen at setup.

06
The big bet

The product IS the translation: plain English → the right automation.

Why it's the moat

  • Plumbing is deterministic code — flows can't be hallucinated.
  • All the fuzziness lives in ~5 arguments: agent · mode · cadence · source · sink.
  • Get that reliably right and the platform feels magic. Get it wrong and it's noise.

What we'll build

  • A dedicated Flow-Planner agent (typed output).
  • A validation gate before anything arms.
  • A benchmark — labeled corpus scored in CI.
  • Pick the right model on accuracy / latency / cost.
07
The big bet — a concrete example

Even the “deterministic plumbing” has a fuzzy seam: mapping each piece's shape.

Every integration returns a different shape. Hand-coding the field paths is a guess that fails silently — the flow “succeeds,” but the agent receives an empty payload.

The bug (real, this week)

  • A gmail push flow armed fine and ran green — but mailbot replied “please provide the email content.”
  • The builder had hard-coded {{trigger.body.subject}}.
  • But the gmail piece nests under message, with different names (text, not body_plain; from is an object). Every field resolved to empty.
  • One hand-written map per piece = one silent failure waiting per piece.

The smarter way (same pattern as NL→Flow)

  • Forward the raw trigger output and let the worker — already an LLM — read it. Zero per-piece mapping to get wrong.
  • Or an LLM / schema step at arm time reads the piece's published output schema and derives the map once, behind a validator.
  • Keep curated maps for clean UX — but always with the raw payload as a safety net, so nothing is ever blank.
  • Lesson: static code is brittle wherever the shape is fuzzy — the NL and the piece payload. LLM proposes · validator gates · the intelligent worker consumes.
