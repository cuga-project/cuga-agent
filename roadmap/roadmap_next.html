Decisions locked today

Architecture
  • AP owns trigger + all sinks. Channels/integrations in and out are AP's; the agent holds no integration creds/tools — it returns a labeled verdict + message, AP routes & sends. (Rejected Route B / agent-self-delivers as the no-build fallback only.)
  • Exception: file-content download — AP moves references, not LLM text; read a file body on a need basis (agent read-tool or an inserted download step).
  • Poll = a new state primitive, not a prompt hack. Build mirrors box_direct (AP schedule = clock; a CUGA endpoint holds per-sub state, fires on transition). /invoke stays untouched; only the poll kind re-points to /poll.

A third role for integrations — the read side

We've been building AP as trigger and sink. The morning-briefing class ("weather + Calendar + Todoist → a briefing") exposes a third role an integration plays: a runtime read/query the agent makes while reasoning. That isn't AP — AP hands events, not query results. It's the agent's MCP tools, per-user. Same bucket as Slack-as-a-source and Box file-content.

Integration roleOwnerExample
TriggerActivepiecesnew email / PR / file fires the flow
SinkActivepiecespost to Slack / send a Gmail
Read / queryCUGA agent + MCPread Calendar, Todoist, Slack history, a file's body — at runtime

Here CUGA does the real work: picks the user, runs the agent, orchestrates the tool calls, reasons the sources into one answer, delivers. AP couldn't do that with any number of pieces. This tier is additive connector work, not a new flow primitive — it's the lightweight-app thesis reaching real multi-source assistants. (Workstream #7.)

Problems we found (in code)

Confirmed gaps
  • Poll state is emulated — no store; wrong semantics (last-tick vs baseline); no no-op suppression in /invoke → "nothing changed" spam. Classifier even misreads the phrasing.
  • Branch not in the live engine — router_step/send_step exist in the spec layer (flows.py) but ap_engine only builds linear trigger→http→publish.
  • Box passes the filename, not the content — the agent judges resume.pdf, not its words.
  • Telegram-push delivery unwired — create_push_flow appends no send-step; direct-only channels (Slack) work via thread_id, AP channels don't.
  • Flow-builder drift — two builders (flows.py vs ap_engine.py) render shapes independently; the #2 router build should consolidate them.
