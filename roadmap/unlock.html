CUGA Events — What you can unlock

This page maps the whole space against what's live now, what's one connect away, and what needs a new agent. Example domains are drawn from the cuga-apps catalog.

6 The genuinely-new combinations (direct backends)

Cells that were closed before this week's direct-Slack + direct-Box + direct-channel-delivery work:

  • Clock → Slack / Discord — any CRON/POLL can now deliver to a direct channel (previously AP-only send-step, and Slack/Discord had no AP connection).
  • Integration IN → direct chat OUT — an AP PUSH (or the opt-in Box direct poll) can deliver its result straight to Slack/Discord (CUGA-side), not just email.
  • Slack as a full conversational channel — inbound and scheduled-delivery target, live-verified.
  • Cross-channel — ask from Discord, get answered in-thread; watch on a timer, deliver to a different channel than you asked from.

7 Honest gaps what "🔨" really means

#GapCloses when…
1Box PUSH (AP) needs the OAuth connect exercised. The concierge arms Box on AP (create_push_flow) → asks you to connect Box (OAuth app + consent). This is the default; the direct poll is the AP-free opt-in.connect Box in AP (OAuth), or use EVENTS_BOX_BACKEND=direct
2Box watcher passes the file name, not its content — the agent can't read the bytes yet (cuga_text_extract_text → File not found). Applies to both backends.a Box download step (AP action, or in box_direct)
3The "🔨 build an agent" examples have the skill (an MCP server or a cuga-app), but no seeded agent advertising it — so the router declines them.a builder registers the agent (skill + channels + integrations)
4Gmail / GitHub / webhook integrations aren't connected in AP.connect Gmail/GitHub (Studio → Integrations) or wire the generic webhook

So an example is ✅ live only when all three hold: a seeded agent advertises the skill, its source + sink are wired, and its integration (if any) is connected. Most cells are one small step from green.
