i What you're running

Three local processes. AP is a long-lived container; CUGA + the registry you start with one script.

ProcessPortStarted byRole
Activepieces (+ postgres + redis)8081scripts/ap_up.shconnections · triggers · delivery
CUGA server (events behind EVENTS_ENABLED)8100scripts/events_up.shconcierge · worker · Studio · /invoke
Tool registry (MCP apps)8001scripts/events_up.shserves the cuga_* MCP tools
AP reaches CUGA at http://host.containers.internal:8100/invoke. Channel webhooks & OAuth callbacks need HTTPS → the scripts start Cloudflare quick-tunnels automatically.

▶ The make shortcuts

Once the code, .env, and the AP container exist (steps below), the day-to-day loop is a root Makefile that wraps the scripts. Run make with no target to list everything.

CommandDoes
make env-checkverify .env has the required keys — offline, no network
make doctorlive credential doctor (preflight.py) — pings each service
make ap / make cugastart Activepieces / CUGA + registry + tunnels
make up (make start)start both, AP first
make channelsconnect + arm every inbound chat channel with a token in .env (run after up)
make reloadbounce only the CUGA server (pick up .env/code) — keeps AP + tunnels, URLs unchanged
make stopstop everything (AP + CUGA + tunnels), keep data
make nukestop and wipe AP volumes (ap_pgdata/ap_redis) + events.db
make status / make logswhat's running + tunnel URLs / tail the runtime logs

make test / make test-alloffline events suite (~60) / all offline tests (events + unit)
make test-livelive e2e — needs the stack up (make up) + creds
The numbered steps below are the from-scratch runbook these shortcuts wrap. First machine: follow them once; after that, live in make up / make stop / make nuke.

0 Get the code & Python env

# from your CUGA checkout root (this repo) cd /path/to/cuga-agent-july uv venv .venv uv pip install -e .

All scripts call .venv/bin/python, so just having the venv populated is enough — no need to keep it "activated".

2 Configure .env

Copy the example and fill in your credentials. The essentials:

# --- LLM (pick your provider; watsonx shown) --- LLM_PROVIDER=watsonx WATSONX_APIKEY=... WATSONX_PROJECT_ID=... WATSONX_URL=... # --- the /invoke seam (any non-empty shared secret) --- GATEWAY_TOKEN=pick-any-random-string HOST_CALLBACK_URL=http://host.containers.internal:8100/invoke # --- Activepieces admin (ap_up.sh signs this up) --- AP_BASE_URL=http://localhost:8081 AP_EMAIL=you@example.com AP_PASSWORD=Sup3rSecret! # --- public HTTPS (Telegram/Slack webhooks) — a cloudflared quick-tunnel to :8100 --- EVENTS_PUBLIC_URL=https://your-tunnel.trycloudflare.com # --- channels & integrations you'll test --- TELEGRAM_BOT_TOKEN=123456:ABC... # @BotFather (AP backend) DISCORD_BOT_TOKEN=... # direct Gateway backend (default, instant); needs MESSAGE CONTENT INTENT SLACK_BOT_TOKEN=xoxb-... # direct backend (default); SLACK_SIGNING_SECRET recommended BOX_DEV_TOKEN=... # direct poll (default); ~60-min dev token, no OAuth app
⚠️ Do NOT set AP_WORKER_TOKEN. Activepieces mints it as a JWT signed with AP_JWT_SECRET. A random string makes the AP worker crash-loop and every channel/schedule arm hangs. Leave it unset — ap_up.sh handles the AP secrets in .ap.env (only AP_ENCRYPTION_KEY + AP_JWT_SECRET).

Per-integration setup (procure → wire → verify → troubleshoot) lives in events_docs/setup/: Slack · Discord · Telegram · Box. Slack & Box default to a direct backend (CUGA↔vendor API, no Activepieces); Telegram & Discord run via AP.

3 Bring up Activepieces

# pg + redis + app on a shared network, a tunnel, and admin sign-up — all in one make ap # = scripts/ap_up.sh

Wait for it to print AP READY and a ✓ AP worker healthy line. It generates .ap.env (stable secrets) on first run.

Verify: curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8081/api/v1/flags → 200.
The tunnel URL is ephemeral — if cloudflared restarts, re-run scripts/ap_up.sh and re-arm any channels.

4 Build the Studio UI

The frontend is served as a pre-built bundle — build it once (and after any UI change).

scripts/frontend_build.sh # pnpm install + webpack build → src/cuga/frontend/dist

5 Bring up CUGA + the registry

# starts the MCP registry (:8001), tunnels, and the CUGA server (:8100) # with EVENTS_ENABLED=1, worker=cuga, seed agents, EVENTS_USER_ID=admin, EVENTS_DB, sandbox timeout make cuga # = scripts/events_up.sh (or make up to start AP + CUGA together) make status # show ports + tunnel URLs make stop # tear down (keep data); make nuke also wipes the DBs
Verify: curl -s http://localhost:8100/api/events/status → {"enabled":true,...}

6 Quick test

Three levels — pick any. All should pass on a healthy stack.

a) Offline suite (no stack needed)

make test # = pytest tests/events -q

Expect 39 passed.

b) Live router end-to-end (uses the running stack)

EVENTS_SERVER_URL=http://localhost:8100 \ GATEWAY_TOKEN=$(grep '^GATEWAY_TOKEN=' .env|cut -d= -f2-|sed 's/ *#.*//'|tr -d ' ') \ .venv/bin/python tests/events/live_server_e2e_check.py

Expect 6/6 checks passed — status, router sees agents, answer-now price, flow create, dedup reuse, decline.

c) The Studio, in your browser

open http://localhost:8100/studio

Tabs: Concierge · Agents · Channels · Integrations · Flows · Examples · Profile · Admin. Try the Agents tab (geobot, pricebot…) and the Concierge tab (toggle Preview to see the plan without arming).

Not :7860. That port is a different repo/checkout. The events Studio is on :8100. If you see "Studio is off," you're on the wrong port or an old cached bundle — go to :8100/studio and hard-refresh (⌘⇧R).

7 Telegram round-trip optional

Prove the full inbound path: message → concierge → CUGA → reply back in Telegram.

# 1) hand your bot token to AP (creates the connection) TOK=$(grep '^TELEGRAM_BOT_TOKEN=' .env|cut -d= -f2-|sed 's/ *#.*//'|tr -d ' ') curl -s -X POST http://localhost:8100/api/events/connect/telegram/token \ -H 'content-type: application/json' -H 'x-user-id: admin' \ -d "{\"token\":\"$TOK\",\"scope\":\"default/default\"}" # 2) arm the inbound flow (registers the Telegram webhook via the tunnel) curl -s -X POST http://localhost:8100/api/events/admin/channels/telegram/arm \ -H 'content-type: application/json' -H 'x-user-id: admin' \ -d '{"scope":"default/default"}'

Then message your bot: what is the capital of Japan? → you get an answer. Try watch bitcoin every 2 minutes and ping me on any move → a scheduled flow delivers back to your chat. More utterances on the Examples page.

! Troubleshooting

Channel/schedule arm hangs ~30s or returns an empty error

The AP worker is crash-looping — almost always because AP_WORKER_TOKEN was set to a non-JWT value. Confirm: podman exec activepieces sh -c "npx pm2 list" — if activepieces-worker shows many restarts, remove AP_WORKER_TOKEN from .ap.env and re-run scripts/ap_up.sh. (The script now gates on worker health.)

"Studio is off" / no Agents tab

You're on :7860 (a different repo) or an old cached bundle. Use http://localhost:8100/studio and hard-refresh. If still off, check curl http://localhost:8100/api/events/status returns JSON (not HTML) with enabled:true.

Telegram webhook won't register ("HTTPS URL required")

AP builds the webhook from its tunnel URL. If the tunnel died, re-run scripts/ap_up.sh (new URL) and re-arm the channel.

arXiv / papers agent times out

External APIs (~5s/call) can exceed the default 30s sandbox timeout. The launcher sets DYNACONF_ADVANCED_FEATURES__SANDBOX_EXECUTION_TIMEOUT=120; raise it if needed.

My flows/subscriptions vanished after a restart

EVENTS_DB must be a file (the launcher sets <repo>/.events.db); the default :memory: is wiped on restart. AP keeps running the flow regardless — it's CUGA's index that's lost.

Port already in use

scripts/events_up.sh --stop and scripts/ap_up.sh --stop, then restart. Override with EVENTS_CUGA_PORT / EVENTS_REGISTRY_PORT / AP_PORT.
